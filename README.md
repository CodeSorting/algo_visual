# Queens Lab · 완전탐색 vs 백트래킹

N×N 체스판에 N개의 퀸을 놓되 서로 공격하지 않도록 배치하는 **모든 해**를 찾습니다. 같은 문제를 두 가지 탐색 방식으로 풀면서 체스판, 배열과 실행 코드를 한 단계씩 함께 확인하는 알고리즘 과제 A용 웹 실험실입니다.

화면은 **4-Queens, N=4로 고정**되어 있습니다. 완성 후보를 모두 만든 뒤 충돌을 확인하는 완전탐색과, 중간 충돌에서 하위 탐색을 생략하는 백트래킹의 차이를 관찰합니다. 두 알고리즘은 동일한 **2개의 해**를 모두 찾습니다.

두 알고리즘은 행 0부터 한 행에 퀸 하나씩 놓고, 각 행의 열을 0부터 N−1까지 같은 순서로 시도합니다. 해 하나를 찾은 뒤에도 복귀해 나머지 후보를 탐색하므로 해 목록과 발견 순서가 같습니다.

## 화면을 읽는 순서

1. **알고리즘 탭**에서 완전탐색 또는 백트래킹을 선택합니다. 한 번에 한 알고리즘의 작업 화면을 봅니다.
2. **다음**으로 한 단계씩 진행합니다. 자동 재생보다 단계 이동을 기본 학습 방법으로 사용하세요.
3. 한 화면에 표시된 **3D 체스판 → `q`·점유 배열 → 강조된 실제 코드**를 연결해 읽습니다. 탐색 트리는 현재 후보가 어느 부분 배치에서 나왔는지 보여줍니다.
4. 필요할 때 접힌 설명을 펼쳐 **무엇이 바뀌었고 왜 그 작업을 했는지** 확인합니다.
5. **이전**이나 단계 슬라이더로 돌아가 같은 상태를 다시 확인합니다. 자동 재생은 원하는 경우에만 사용합니다.
6. 다른 알고리즘 탭에서도 같은 부분 배치가 어떻게 처리되는지 찾아 비교합니다.

두 알고리즘은 **서로 독립적인 실행 기록**을 갖습니다. 단계 슬라이더는 UI 이벤트를 탐색하는 도구입니다. 같은 단계 번호가 같은 후보 배치, 같은 진척률 또는 같은 계산량을 뜻하지는 않습니다. 두 방식은 검사·배치·복귀 이벤트의 구성이 다릅니다.

## 공통 표현: 열 배열 `q`

`q[row] = col`은 `row`행의 퀸이 `col`열에 있다는 뜻입니다. **내부 데이터와 화면의 행·열 번호는 모두 0부터** 셉니다. 빈 행은 내부에서 `-1`로 표시하며 아직 퀸을 놓지 않은 상태입니다.

예를 들어 `q = [1, 3, 0, 2]`는 `(0,1), (1,3), (2,0), (3,2)`에 퀸을 둔 완성 배치이며, 4-Queens의 해 중 하나입니다. 한 행에 하나씩 놓기 때문에 행 충돌은 표현 자체에서 제외됩니다. 남은 제약은 열과 두 방향 대각선 충돌입니다.

| 상태 | 길이 | 의미 |
| --- | --- | --- |
| `q` | N | 각 행에 놓은 퀸의 열 |
| 열 상태 | N | 해당 열의 사용 여부 |
| 차 대각선 상태 | 2N−1 | `row−col+N−1` 인덱스로 식별하는 대각선 |
| 합 대각선 상태 | 2N−1 | `row+col` 인덱스로 식별하는 대각선 |

같은 차 대각선 위의 칸들은 `row−col`이 같고, 같은 합 대각선 위의 칸들은 `row+col`이 같습니다. `row−col`의 범위가 `−(N−1)`부터 `N−1`까지이므로 `N−1`을 더해 배열 인덱스를 0부터 `2N−2`까지로 옮깁니다.

**완전탐색 쪽의 점유 상태는 현재 배치에서 계산한 설명용 정보입니다. 이 배열을 이용해 후보를 미리 버리지 않습니다.** 백트래킹은 이 상태를 실제로 갱신하고 참조하여 다음 후보를 검사합니다.

백트래킹은 후보를 `q[row]`에 임시로 넣은 뒤 검사하고, 안전하다고 확인한 **commit 단계**에서 점유 배열을 갱신합니다. 따라서 검사 중에는 `q`에 새 후보가 있어도 점유 배열은 앞선 행들의 확정된 퀸만 나타냅니다. 충돌 후보를 버릴 때는 임시 `q[row]`만 비우고, 안전한 배치에서 복귀할 때는 `q[row]`와 세 점유 표시를 함께 되돌립니다.

## 1. 완전탐색: 완성한 뒤 모든 퀸 쌍 검사

이 프로젝트의 비교 기준은 **각 행에서 N개 열 중 하나를 골라 N^N개의 완성 열 배열을 모두 만든 뒤 검사**하는 방식입니다. N²개 칸 중 N개를 고르는 별도의 완전탐색이나, 열 중복을 이미 제거한 순열 탐색과 구분하세요.

```text
enumerate(row):
    if row == N:
        valid = true
        for i = 0 .. N−1:
            for j = i+1 .. N−1:
                if q[i] == q[j] or abs(q[i]−q[j]) == j−i:
                    valid = false
                // 충돌을 발견해도 남은 쌍을 모두 검사한다
        if valid:
            해를 기록한다
        return

    for col = 0 .. N−1:
        q[row] = col
        enumerate(row+1)
        q[row]를 비운다
```

예를 들어 `q = [0, 0, _, _]`는 이미 같은 열 충돌이 보입니다. 그래도 완전탐색은 남은 두 행의 열을 모두 시도하여 **16개의 완성 배열**을 만들고 각각 검사합니다. 이 충돌을 화면에서 표시하더라도 탐색을 생략하는 것은 아닙니다.

## 2. 백트래킹: 배치를 확정하기 전에 충돌 검사

```text
search(row):
    if row == N:
        해를 기록한다
        return

    for col = 0 .. N−1:
        q[row] = col  // 화면에 검사할 임시 후보 표시
        d1 = row−col+N−1
        d2 = row+col
        if usedCol[col] or usedDiff[d1] or usedSum[d2]:
            if row < N−1:
                이 후보 아래의 완성 배치들을 만들지 않고 생략한다
            else:
                이미 N개 행을 채운 이 완성 후보를 거부한다
            q[row]를 비운다
            continue

        usedCol[col], usedDiff[d1], usedSum[d2]를 사용 중으로 표시
        search(row+1)
        세 표시를 해제하고 q[row]를 비운다
```

배열 세 칸의 사용 여부만 확인하므로 후보 하나의 충돌 검사는 `O(1)`입니다. 충돌하는 부분 배치는 나머지 퀸을 어디에 놓아도 유효한 해가 될 수 없으므로 하위 탐색을 생략해도 해를 잃지 않습니다. 단, 마지막 행에 임시 후보를 놓았다면 `q`의 N개 행은 이미 모두 채워진 상태입니다. 이때의 충돌 거부는 완성 후보 자체를 검사한 것이므로, 그 후보를 “만들지 않았다”고 세지 않습니다. 재귀 호출이 끝나면 배치와 점유 상태를 원래대로 되돌려 다음 열을 시도합니다.

## 복잡도: 이 구현을 기준으로 비교

화면은 N=4의 작은 입력을 사용하지만, 다음 복잡도는 같은 알고리즘을 일반적인 N에 적용할 때의 분석입니다.

| 항목 | 완전탐색 | 백트래킹 |
| --- | --- | --- |
| 탐색 방식 | N^N개 완성 배열을 모두 검사 | 충돌 없는 부분 배치만 확장 |
| 후보·배치 검사 | 완성 배열마다 N(N−1)/2개의 모든 퀸 쌍 | 후보마다 점유 배열 3개를 `O(1)`에 조회 |
| 시간 | **Θ(N²·N^N)** | **O(N·N!)**의 보수적 상한 |
| 작업 공간 | `q`와 재귀 깊이 **O(N)** | `q`, 점유 배열과 재귀 깊이 **O(N)** |

완전탐색은 완성 배열 N^N개 각각에 대해 Θ(N²)개의 쌍을 반드시 검사합니다. 충돌 발견 직후 검사 루프를 중단하지 않는 현재 구현에 맞춘 분석입니다.

백트래킹의 깊이 r에서 열이 중복되지 않는 부분 배치 수는 `P(N,r)=N!/(N−r)!`개 이하입니다. 대각선 제약은 이를 더 줄입니다. 각 재귀 호출이 N개 열을 순회하므로 r=0부터 N−1까지의 `O(N × Σ P(N,r))`를 상한으로 잡아 `O(N·N!)`로 설명합니다. 이는 보수적인 상한이며 실제로 그만큼 전부 탐색한다는 뜻은 아닙니다. 가지치기로 탐색량이 줄어도 이 모든 해 탐색을 다항 시간 알고리즘이라고 설명하면 안 됩니다.

위 작업 공간은 **실행 기록과 출력 해 저장을 제외한 알고리즘 자체**의 분석입니다. 이 페이지는 이전 단계로 돌아가기 위해 상태 스냅샷과 트리 데이터를 저장합니다. 이벤트 수를 T라고 할 때 N개 규모의 배열을 매번 복사해 저장하면 그 부분만 `O(TN)` 공간이 필요합니다. 모든 해를 배열로 보관하는 공간도 해의 수에 비례합니다. 따라서 웹페이지 전체 메모리가 O(N)이라고 쓰지 마세요.

## 비교 지표와 같은 단위의 해석

| 지표 | 의미 |
| --- | --- |
| `attempts` | 행의 열 후보를 시도한 횟수. 두 방식에서 후보가 이후 처리되는 방식은 다름 |
| `fullCandidates` | 마지막 행에 임시 후보를 놓아 `q`의 N개 행을 실제로 모두 채운 횟수. 나중에 거부되는 후보도 포함 |
| `skippedCandidates` | 마지막 행 이전의 충돌 때문에 **실제로 만들지 않은 완성 후보** 수 |
| 해 수 | 최종 제약을 만족하는 완성 보드 수. N=4에서는 두 알고리즘 모두 2 |
| UI 단계 수 | 배치·검사·복귀 등의 화면 이벤트 수. CPU 명령 수나 시간 아님 |

공통 비교 단위는 **가능한 N^N개의 완성 열 배열**입니다. `fullCandidates`는 실제로 만든 배열, `skippedCandidates`는 중간 가지치기로 만들지 않은 배열을 셉니다. 0부터 시작하는 행 r이 `N−1`보다 작을 때 충돌 후보를 버리면, 아직 결정하지 않은 `N−r−1`개 행에 해당하는 `N^(N−r−1)`개를 `skippedCandidates`에 더합니다. 각 배열은 처음 충돌하는 접두 배치에서 한 번만 제외되므로 중복 계산하지 않습니다.

전체 실행이 끝나면 다음 관계가 성립해야 합니다.

```text
완전탐색 fullCandidates = N^N, skippedCandidates = 0
백트래킹 fullCandidates + skippedCandidates = N^N
실제로 만든 후보 중 거부된 수 = fullCandidates − 해 수
두 알고리즘 모두 같은 순서로 같은 2개의 해를 보고한다
```

| 입력 | 완전탐색이 실제로 만든 후보 | 백트래킹이 실제로 만든 후보 | 백트래킹이 만들지 않은 후보 | 백트래킹의 완성 후보 중 거부 | 해 수 |
| --- | ---: | ---: | ---: | ---: | ---: |
| N=4 | 256 | 16 | 240 | 14 | 2 |

위 수는 코어를 끝까지 실행해 확인한 값입니다. `256 = 16 + 240`으로 같은 후보 공간을 나눕니다. 백트래킹이 실제로 N개 행을 모두 채운 후보는 **16개**이고, 그중 **14개**를 마지막 행 검사에서 거부하며 **2개**를 해로 기록합니다. 나머지 **240개 후보**는 앞선 행에서 충돌이 확인되어 만들지 않습니다.

코어에는 구현 흐름을 나타내는 `fullBoards`와 `prunedLeaves`도 있습니다. `fullBoards`는 **재귀 종료 조건까지 들어간 보드**를 셉니다. 완전탐색에서는 모든 완성 후보 256개가 들어가지만, 백트래킹에서는 마지막 행 검사까지 통과한 해 2개만 들어갑니다. `prunedLeaves`는 불가능하다고 판정한 잎의 수로, 중간에서 만들지 않은 240개와 **이미 만든 뒤 마지막 행에서 거부한 14개**를 모두 포함하여 254입니다. 따라서 `prunedLeaves` 전체를 실제로 만들지 않은 후보 수로 읽으면 안 됩니다. 화면의 비교 차트는 `fullCandidates`와 `skippedCandidates`를 사용합니다.

**완전탐색의 완성 후보 수 ÷ 백트래킹의 UI 단계 수**처럼 서로 다른 단위로 속도 향상 배수를 계산하지 마세요. 자동 재생에서 어느 쪽이 먼저 끝나는지도 계산 성능의 측정값이 아닙니다.

## 4-Queens에서 추천하는 관찰 장면

1. **같은 초기 선택**: 0행의 0열을 고르고 다음 행으로 이동한다.
2. **일찍 발견한 열 충돌**: `[0,0,_,_]`에서 완전탐색은 남은 두 행을 계속 채운다. 백트래킹은 열 점유 상태를 보고 그 아래 16개 완성 후보를 만들지 않는다.
3. **마지막 행의 대각선 검사**: `[0,3,1,2]`는 네 행이 이미 모두 채워진 후보이다. `(2,1)`과 `(3,2)`의 `row−col+N−1`이 4로 같아 충돌하므로 거부한다. 이 후보는 실제로 만들어졌다는 점을 구분한다.
4. **해 발견과 복귀**: `[1,3,0,2]`를 해로 기록한 뒤에도 탐색을 계속한다. 복귀할 때 퀸 제거와 점유 표시 해제를 확인한다.
5. **탐색 종료**: `[1,3,0,2]`, `[2,0,3,1]`의 두 해를 같은 순서로 찾았는지 확인한다. 백트래킹의 `16 + 240 = 256`과 완전탐색의 256개 완성 후보 검사를 비교한다.

같은 단계 번호에서 두 알고리즘의 `q`가 다를 수 있습니다. 같은 후보를 대조하고 싶다면 각 알고리즘의 기록을 앞뒤로 움직여 해당 후보 장면을 찾아 읽으세요. 화면의 N은 4로 고정되어 있어 크기를 선택하는 단계는 없습니다.

## 로컬 실행과 GitHub Pages

이 프로젝트는 서버 계산이나 데이터베이스가 없는 정적 웹페이지입니다. 설치·빌드 과정은 없습니다. 안정적인 로컬 미리보기는 `index.html`이 있는 폴더에서 아래처럼 실행합니다.

```powershell
python -m http.server 8000
```

브라우저에서 `http://localhost:8000`을 여세요. Python 명령이 인식되지 않으면 설치된 Python 실행 파일의 전체 경로를 사용하면 됩니다.

GitHub Pages로 배포하려면 다음과 같이 설정합니다.

1. GitHub에 새 저장소를 만들고, 이 폴더의 **내용물**을 `main` 브랜치의 루트에 업로드합니다. `index.html`이 저장소 루트에 있어야 합니다.
2. 루트에 `.nojekyll` 파일을 포함합니다.
3. 저장소의 **Settings → Pages → Build and deployment → Source**에서 **Deploy from a branch**를 선택합니다.
4. **main**, **/(root)**를 선택하고 **Save**합니다.
5. 배포가 끝나면 Pages 설정에 표시된 실제 주소를 확인합니다. 프로젝트 사이트의 일반적인 주소 형식은 `https://<계정명>.github.io/<저장소명>/`입니다.
6. 배포 주소에서 알고리즘 탭, 이전·다음·슬라이더, 배열·코드 동기화와 탐색 종료 상태를 확인합니다. 채점이 끝날 때까지 링크를 유지합니다.

무료 개인 계정에서 Pages를 사용하는 기본 선택은 공개 저장소입니다. 학번 등 보고서용 개인정보를 웹페이지 소스에 넣을 필요는 없습니다.

## 과제 A 보고서 체크리스트

- [ ] 선택 주제와 알고리즘, N-Queens라는 공통 문제를 설명했다.
- [ ] 강의에서 이미 비교한 조합인지 강의 자료와 대조했다.
- [ ] 고정된 N=4의 작은 입력으로 동작 과정을 설명했다. 입력 퀸 수 4는 10개 이하이다.
- [ ] 첫 해에서 멈추지 않고 두 해를 모두 찾는다는 공통 종료 조건을 설명했다.
- [ ] 완전탐색의 기준을 N^N개 열 배열의 완성 후 전수 검사로 명확히 정의했다.
- [ ] 두 핵심 코드와 구현에 맞는 시간·공간 복잡도, 그 이유를 넣었다.
- [ ] 각 장면에 **무엇을 했고 왜 그렇게 했는지** 본인의 말로 설명했다.
- [ ] 체스판만 보여주지 않고 `q`, 점유 배열, 탐색 가지와 코드의 관계를 설명했다.
- [ ] 마지막 행에서 이미 완성한 후보의 거부와, 앞선 행에서 만들지 않은 하위 후보를 구분했다.
- [ ] 직접 확인한 지표를 같은 단위로 비교하고, UI 단계 수를 실행 시간으로 해석하지 않았다.
- [ ] 배포했다면 실제 URL과 링크가 안 열릴 때를 대비한 **핵심 이미지 3~5장**을 PDF에 넣었다.
- [ ] 영상·GIF를 선택했다면 영상 1~3분 또는 GIF 30초~1분의 안내 기준을 확인했다.
- [ ] 학번·이름·분반, 출처와 AI 활용 내용을 포함하고 스스로 확인한 분석을 작성했다.
- [ ] 최종 제출물인 **PDF 1개**를 LMS에 제출한다. 웹 링크만 제출하는 과제가 아니다.

보고서는 문제와 상태 표현 → 두 핵심 코드 → 복잡도 비교 → 4-Queens 단계별 장면 → 전체 결과와 후보 공간 분할 → 본인의 해석과 참고 자료 순으로 구성할 수 있습니다. 배포는 선택 사항이며, 과제의 핵심은 내부 동작에 대한 설명과 분석입니다.
